# 链路加固第二阶段：运行与恢复可靠性

## 本阶段交付

- 启动/恢复时，`running` 状态、新 `execution_id` 和启动事件在同一 PostgreSQL 事务内提交。事件失败会回滚认领；创建后台任务失败则补偿为 `interrupted`，补偿存储失败由后续对账处理。
- 章节产物与对应事件原子提交；完成时的最终产物、状态与终态事件也原子提交。不会先展示新草稿再丢失它对应的事件。
- 模型调用诊断、章节产物和 Checkpoint 写入均核对本次执行 ID。Checkpoint 写入期间持有业务行锁，防止检查之后、写入之前被新的执行替换。写入默认 30 秒超时；数据库语句与锁等待也有限时。
- 任务异常退出且终态无法落库时，不会永远停留在 `running`：后台对账会在数据库恢复后将无对应本地任务的记录改为 `interrupted`，同步发出事件。对账不会自动调用模型或推进研究。
- 关闭服务会取消后台任务并最终对账，也覆盖“协程尚未开始就被取消”和“关闭时仍在认领”的窗口。尚未启动运行器就失败的清理不对账、不更改旧 Run。

## 单实例与所有权

同一业务数据库只允许一个 API 进程、一个 Uvicorn worker。API 使用独立 PostgreSQL 连接持有数据库级 advisory lock；第二个实例无法取得锁，拒绝启动，不会把第一个实例的任务误标为失联。此连接不从业务池借用，部署需额外预留一个数据库连接。需要直连或支持会话级锁的连接方式，不支持事务池化代理。

每 5 秒开始一轮所有权检查/任务对账。数据库不可达、锁丢失或无法确认所有权时，当前进程停止接收启动/恢复请求并取消本地任务；健康检查返回不可用。此时不自动重新抢锁，应排查数据库后重启。周期不是故障发现的硬实时承诺，还受探测、锁等待和事件循环调度影响。仅业务连接池故障、但所有权仍正常时，对账会在下轮重试。

服务重启成功后将遗留 `running` 标记为 `interrupted`，用户再主动点击“从 Checkpoint 恢复”。不是分布式调度器，不支持多 worker 并发接管。独立 CLI 没有 API 的业务执行所有权协议，不要用 CLI 并发写同一 Run/Checkpoint。

## 持久化与健康状态

API 启动必须成功初始化文件型 SQLite 或 PostgreSQL Checkpoint；不接受 `memory`、`none`、Redis 或未知后端，也不允许存储失败后静默以内存模式提供 API。CLI 工厂的调试降级行为仍保留，与 API 的恢复承诺区分。

`GET /api/health` 同时检查业务库、实际 Checkpoint 后端及持久化能力、实例锁、后台监视器和对账状态。任一不满足则返回 HTTP 503；前端定期刷新此状态，SQLite 不再因硬编码 PostgreSQL 检查而显示异常。这里只验证连接/读取能力，不是持续写入探针，也不能证明磁盘永不损坏或数据备份完整。

恢复时没有 Checkpoint 分两类：

- 没有章节、报告、审校、模型诊断或实质进度事件：视为启动后、首个 Checkpoint 前中断，可用原问题/父上下文在同一个 Run 初始化。
- 已有研究进度或模型调用记录：明确报错，拒绝静默从头重做。应检查原 Checkpoint 配置和备份，而不是删除业务产物。

## 部署和原任务恢复

1. 备份本项目数据库与 Checkpoint。停止旧版 API 进程；旧代码不参与新锁协议，不能与新版并行运行。
2. 在 `multi-agent` 环境启动后端，只运行一个 worker。保留原 `POSTGRES_DB_URL`、`CHECKPOINT_BACKEND` 和 SQLite 路径（如使用 SQLite），不要把存储切到空库。
3. 确认 `/api/health` 返回 200，浏览器 Ctrl+F5。
4. 打开原 Run，核对现有章节，再点击“从 Checkpoint 恢复”。本次开发验收没有替用户执行这一步。

本阶段没有新增业务数据库列；沿用前阶段的 `execution_id`、事件和诊断表。启动仍会执行项目已有的幂等建表/升级逻辑。

## 验证与保证边界

2026-10-03 验收：Python 全套 134 项通过、4 项可选 PostgreSQL 测试默认跳过；其中本阶段选定的 3 项隔离 PostgreSQL 测试已单独启用并通过。前端 DOM 契约 9 项通过，相关 Python 静态检查与 `git diff --check` 通过。未启动新版生产 API，也未进行真实模型整报告验收。

离线测试覆盖启动事务故障、任务创建失败、取消竞态、终态存储失败后的对账、锁丢失、旧执行写入、Checkpoint 超时、持久化降级拒绝和缺失 Checkpoint 的两条恢复路径。模型/检索使用替身。

真实 PostgreSQL 测试在私有随机 schema 的回滚事务内验证启动及产物事件原子性、执行 ID 隔离与对账；另用随机测试 advisory lock 验证独立测试子进程退出后锁可释放。没有终止用户的 API 进程，测试 schema 随事务回滚撤销，不保留研究数据。原失败 Run 与它的 Checkpoint 未修改，没有付费模型调用，也没有访问隔壁知识库目录。

不承诺外部调用 exactly-once：进程可能在模型已计费、响应尚未保存时退出，恢复后可能重复调用。业务库与 Checkpoint 是不同存储事务，不能宣称全链路分布式原子性；恢复快照仍用于对齐已保存的图状态与业务展示。执行 ID 和行锁防止协议内的过期执行覆盖新执行，不替代备份、数据库容灾或对不遵守协议的旧进程的隔离。
