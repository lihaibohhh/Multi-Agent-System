# 模型输出校验与 Checkpoint 恢复修复

后续升级已将格式与业务校验统一，含引文定位、规划/章节 ID 检查和共享纠正预算，详见 [链路加固第一阶段](business-validation-hardening.md)。本文保留首次修复的背景和部署步骤。

## 问题与处理

本次失败来自 `SectionReview.search_queries`：实际模型返回 3 个检索词，而模型定义最多允许 2 个。原来的手写提示没有完整说明约束，包装函数又隐藏了具体校验错误。HTTP 200 仅说明收到了服务响应，不代表 JSON 满足业务模型。

- 所有章节结构化调用都在提示中注入完整 JSON Schema，包括嵌套类型、枚举和数组长度。
- 保留真实 LangChain/Pydantic 校验。格式错误允许最多两次纠正（连同首次最多三次），将具体字段错误反馈给模型。不会直接截断检索词或把 `revise` 改成 `pass`。
- 请求/鉴权失败不当成格式问题重复调用；输出达到长度上限时明确失败，不做无效的格式重试。包括 SDK 在返回解析结果前抛出的长度异常。
- 超限后保留失败状态和 Checkpoint，公开错误包含字段原因及诊断 ID，不包含原始研究内容。

恢复还有一个独立问题：从事件 0 重新订阅会读到历史 `error`，导致页面提前关闭新执行的连接。

- 新增 `GET /api/runs/{run_id}/snapshot`，返回 `{run, cursor}`；两者由同一数据库快照读取。
- 页面先加载快照，再从 `/stream?after={cursor}` 读取新增事件。终态快照直接展示结果或错误，不重放旧错误。
- 每次启动/恢复分配 `execution_id`，前端忽略旧执行、重复事件和已关闭连接的回调；切换任务时也忽略迟到的旧请求。
- 终态和对应事件在同一事务中提交，旧执行不能覆盖新执行；Run Tree 与当前任务状态同步更新。同 Run 事件写入按行锁排序，避免先取得较小序号的事件迟提交而被游标跳过。

## 私有诊断与用量

API RunService 将每次章节模型调用写入 `research_model_attempts`，包括 Run/执行/调用/诊断 ID、节点、模型、次数、字段错误、返回用量和最多 16,000 字符的原始输出。不会保存完整提示；对已配置密钥和常见 token 格式做脱敏，但不能保证识别任意敏感文本。该表没有公开读取 API，也不进入 SSE 或普通 Run 响应。请保护本项目数据库的权限和备份；目前没有自动清理期限，研究内容可能持续保留。

`research_runs.model_usage` 累计已记录调用的 `attempts`、`tokens` 和未知用量次数 `unknown`。即使节点失败，其已知用量也不会随节点状态回滚丢失；恢复继续累计。不追补升级前的调用，不完整覆盖 SDK 内部 HTTP 重试、取消或未返回用量的请求，不能作为供应商精确账单或预算硬上限。独立 CLI 调用未绑定数据库诊断写入器，不提供同样的持久审计。

## 升级与恢复原任务

1. 备份本项目 PostgreSQL 和所用的 Checkpoint 存储；不要操作隔壁知识库。
2. 停止旧后端并使用 `multi-agent` 环境重新启动。启动时执行幂等增量建表/加列：`execution_id`、`model_usage`、`research_model_attempts`，并保留原 Run、章节和 Checkpoint。

   ```powershell
   conda run -n multi-agent python -m uvicorn multi_agent_research.api.server:app --host 127.0.0.1 --port 8000 --loop multi_agent_research.api.event_loop:selector_loop_factory
   ```

3. 浏览器按 Ctrl+F5 刷新，加载原 Session，在 Run Tree 中选择失败的原 Run，点击“从 Checkpoint 恢复”。不要创建新 Run，也不需要清空数据库。
4. 恢复从失败节点继续，不重新执行所有已完成步骤。对于本次首章待审校的任务，会重新审校已保存草稿；若判定需要补证或改稿，按既有次数限制进入相应步骤。恢复会继续产生模型调用费用。

代码修复不等于已部署；旧后端进程不会自动使用新代码。本次验证没有重启用户后端、迁移生产业务表或恢复原 Run。

## 验证与边界

- 自动测试覆盖真实 LangChain/Pydantic 解析链（HTTP 替身）、数组超限纠正、错误 JSON/枚举/类型、重试耗尽、输出截断、脱敏和失败用量。
- Node DOM 契约测试覆盖恢复游标、历史错误、旧连接、Run Tree 和任务切换；不是浏览器视觉验收。
- PostgreSQL 隔离测试在临时 schema 内验证幂等建表、用量去重、终态事务回滚和旧执行隔离，最终整体回滚，验证 schema 已消失，不修改生产业务数据。
- 对失败 Run 的真实 Checkpoint 只读加载后，单独调用修复后的 DeepSeek 审校入口：首次输出通过校验，返回 `revise` 和 2 条检索词。这不是整份报告完成验收，也没有把结果写回原 Run。

以上修复可以消除已定位的提示遗漏和旧事件误处理，但不能保证大模型永不输出无效数据、网络永不失败或审校结论一定正确。目标是降低格式失败率，并让剩余失败有具体原因、有限成本、可靠记录和可恢复入口，而不是失败后强行发布通过的报告。
