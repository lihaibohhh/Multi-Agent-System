# 可审计追加 Token 预算（2026-10-08）

## 行为与边界

`POST /api/runs/{run_id}/budget/increase` 接收：

```json
{
  "confirm": true,
  "request_id": "a-unique-request-id",
  "expected_tokens": 500000,
  "new_tokens": 600000,
  "reason": "明确批准继续研究所需的额外额度"
}
```

- 新值是**总上限**，不是追加量；只允许增加 Token 上限，不修改模型/检索次数等其他限制。
- 必须明确确认并提供原因；旧预算必须先走显式迁移。当前目标 Run 执行中不允许修改，先暂停。
- 锁定目标 Run，再锁共享账户；比较用户确认的 expected_tokens 与当前真实上限，过期请求返回 409，防止不同页面/子 Run 覆盖彼此的更新。
- 相同 request_id 和相同参数重试幂等；同 ID 不同内容返回冲突。重复提交不会重复追加，也不会再次改变任务状态。
- 账户 policy.tokens、幂等凭据与 `budget_increased` 审计事件在一个事务中提交；事件保存失败，全体回滚。
- 只调整同研究共享账户。保留累计调用数、已知 Token、未知预留、历史不完整标记以及全部研究成果。其他共享子 Run 下次读取可见新额度；不同研究账户不受影响。
- 目标 Run 原来是 budget_limited 时转为 paused 并清除当前阻断提示，原失败事件留存；不启动执行、不重置执行时限、不修改 Checkpoint。其他共享 Run 的状态不随之改写。
- 未解决其他预算限制时恢复仍可能被拒绝。增加 Token 不等于增加模型调用次数，也不保证后续研究一定成功。

前端增加“追加共享 Token 额度”按钮，显示当前上限和占用，输入新总上限、原因后再次确认。网络响应不确定时复用请求 ID，服务端 CAS 也拒绝过期额度。新增接口需后端加载新代码；功能沿用项目当前访问边界，不提供强身份认证审计，不应把未鉴权开发服务直接暴露公网。

## 预估与缺口可观测性

Token 准入失败现在明确返回剩余、所需预留、差额及“请求未发送”。事件附带 `budget_block`，包括估算方法与节点标签。预留仍使用 UTF-8 字节长度、最大输出和安全余量，是保守准入估计，不是实际 Token 分词结果。

本阶段没有将其他模型的 tokenizer 或固定中文字数比例冒充 DeepSeek 精确计数；模型匹配的分词估算与校准放到下一阶段。在响应有 usage 时仍按真实已知用量结算，结果未知的调用仍保留预留。
