# 章节局部继续与证据更新（第三阶段，2026-10-08）

## 操作边界

所有操作显式创建子 Run，随后另行启动。原 Run/报告/Checkpoint 不变，父子共用 `budget_id`。普通断点恢复仍使用原 Run 的 `/resume`，不必创建子 Run。

| 模式 | 本次执行 | 保留边界 |
| --- | --- | --- |
| `continue` 选择本章继续 | 复用已有证据或待审草稿，完成目标章及前置条件满足的依赖章 | 不重做无关章，不重置已用章节轮次、查询尝试和研究预算 |
| `supplement` 仅补证据 | 一轮检索及一次分析，保存候选证据和缺口 | 不改正文/旧 Claim，不宣称旧结论重新核验，不自动重写依赖章 |
| `refresh` 刷新来源并修订 | 清空本次候选池，重新检索、修订目标章，更新受影响依赖章 | 不把旧来源冒充新检索；没有结果时不回退旧正文作为新结论 |

补证据/刷新获得新的有界章节轮次，但模型次数、检索次数、Token 已知消耗和未知预留始终累计到同一研究账户。创建操作时快照章节策略；`continue` 优先继承来源的章节策略和使用进度。

本轮返回来源最多 8 条优先进入总计 15 条来源视图，其余按相关性补齐，防止旧高分资料挤掉全部新资料。这不保证新来源真实或新近发布；检索时间不是文档发布日期。

## 接口与页面

```http
POST /api/runs/{source_run_id}/sections/{section_id}/operations
Content-Type: application/json

{"mode":"supplement","instruction":"补充最新年度成本数据并保留反证","run_id":"可选的新ID"}
```

返回 `201 created`，不立即调用模型或检索。`parent_context.section_operation` 包含目标 `target`、本次执行章 `work_ids`、受影响章 `affected_ids`、来源事件游标 `source_cursor`、章节策略 `section_policy`。受影响章可能暂不执行。

核对后调用新 Run 的 `/start`；失败/暂停后使用新 Run 的 `/resume`。页面已停止或已完成 Run 的章节展开区有三个操作按钮；至少填写 5 字说明，创建后再核对并启动。候选证据单独展示，安全文本渲染；旧正文和 Claim 在待更新状态下仅是历史。

原 `/revisions` 接口继续保留，仅面向已完成的完整报告。

## 阶段产物不等于完整报告

补证据后目标章为 `evidence_ready`（证据分析通过）或 `waiting_evidence`（仍有缺口/本次无新结果）。直接/间接依赖章保守标为 `stale`，不假定旧综合结论仍有效。

局部操作结束时 Run 可以为 `completed`，这里只表示操作完成。若还有未完成章，`report_quality=partial`，输出“章节研究阶段产物”，没有全篇审校通过的承诺。页面 Run 树显示“局部操作完成”。阶段产物不能通过普通继承/旧修订入口当成完整报告；在这个新 Run 上选择下一章继续或补证据。

全部章节完成且依赖版本一致后，才进入全篇审校和正式装配。选中章有未完成前置章时拒绝并列出前置章。下游若还依赖无关未完成章，只标记待重建，不擅自扩大任务。旧版产物缺少精确依赖时，保守认为依赖此前所有章节。

## 可靠性

- 运行中不能创建操作，返回 409。未完成源 Run 读取真实 Checkpoint；找不到可用章节检查点则拒绝，不从滞后页面猜测。
- 创建子 Run 的事务锁定父 Run，复核状态与事件游标；父任务变化时拒绝旧快照。
- 同一来源快照、同一目标只允许创建一个 `continue` 子 Run；重复提交提示打开已有任务，避免双击生成多份继续任务。
- `continue` 按精确参数继承父 Run 查询成果及失败尝试历史。成功重放无新 HTTP/额度；剩余尝试受共享账户及原查询上限约束。
- 新刷新/补证据是显式新操作，允许新请求且累计费用；普通 `/resume` 不自动刷新、不退款、不清除未知预留。
- 来源时间未知仍显示未知，旧来源和正文在父 Run/草稿历史保留。
